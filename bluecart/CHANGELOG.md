어떤 배포본을 받으셨는지에 따라 덮어써야 할 파일이 다릅니다.
확실하지 않으면 아래 명령으로 대조하세요.

```cmd
php dev\verify.php
```

## 2026-09-23 · 슬랙 제목에 `[BlueCart]` 꼬리표

`#blue_inbox` 에는 여러 시스템의 알림이 모입니다. '검토 승인' 같은 제목은 그
자체로는 어느 시스템 것인지 알 수 없어, 본문까지 읽어야 가려낼 수 있었습니다.

```
:white_check_mark: *[BlueCart] 검토 승인*
```

- 꼬리표 문구는 `BC_SLACK_LABEL` 한 곳에 있습니다. 비우면 붙지 않습니다
- 꼬리표는 제목 **안**(굵게)에 넣습니다. 밖에 두면 굵기가 끊겨 두 줄처럼 읽힙니다
- 알림 배너와 목록 미리보기가 읽는 `text` 도 blocks 와 같게 맞췄습니다.
  전에는 꼬리표 없는 원문이 배너에 떴는데, 어느 시스템인지는 거기서 먼저
  보여야 합니다

이메일 제목은 그대로입니다(`[물품구매 <요청번호>] …`).

**덮어쓸 파일**

```
includes/workflow.php
includes/notify/SlackChannel.php
```

- `header` 블록을 없애고 **mrkdwn 한 덩어리**로 보냅니다

이메일 본문은 그대로입니다. 목록 기호는 슬랙으로 보낼 때만 붙습니다.

## 2026-09-22 · 슬랙 봇 토큰을 관리자 화면에서 넣습니다

지금까지 슬랙 봇 토큰과 Webhook URL 은 `config.php`(또는 환경변수)에만 적을 수
있었습니다. 알림을 켜고 끄는 건 화면에서 하는데 정작 **연결에 필요한 값은 서버에
들어가야** 해서, 관리자가 혼자 끝내지 못하는 설정이 하나 남아 있었습니다.

관리자 탭 → 알림 설정에 **슬랙 봇 토큰 · 슬랙 Webhook URL** 칸을 넣었습니다.

- 읽는 순서는 **화면에서 넣은 값 → `config.php`** 입니다. 이미 설정 파일이나
  환경변수로 넣어 두었다면 그대로 동작하고, 화면은 "설정 파일에 있음" 으로만
  표시합니다(화면에서 지울 수 없습니다)
- 저장한 값은 **AES-256-GCM 으로 암호화**해서 `bc_setting` 에 넣습니다. 포털이
  개인 슬랙 토큰에 쓰는 것과 같은 방식이고, 포털 모듈로 동작할 때는 포털
  `config.php` 의 `key` 를 그대로 씁니다. 단독으로 돌 때는
  `config/secret.local.php` 를 최초 1회 자동으로 만듭니다
- 원문은 **어떤 응답에도 실어 보내지 않습니다.** 설정 여부와 가린 표기
  (`xoxb-••••1a2b`)만 내려갑니다
- 입력칸을 **비워 두고 저장하면 기존 값이 그대로** 남습니다. 지울 때는 옆의
  "지우기" 를 누릅니다
- 붙여넣기 실수를 잡으려고 형식을 검사합니다. 토큰은 `xoxb-`(`xox?-`) 로
  시작해야 하고, Webhook 은 `https://hooks.slack.com/services/...` 여야 합니다

`notify.enabled` 는 그대로 설정 파일에만 둡니다. 알림 전체를 멈추는 스위치라
화면에서 실수로 끄는 자리에 두지 않았습니다.

**덮어쓸 파일**

```
includes/secret.php          (새 파일)
includes/bootstrap.php
includes/model/Setting.php
includes/notify/SlackChannel.php
api/notify_settings.php
views/admin.php
assets/app.js
assets/app.css
```

DB 스키마는 그대로입니다(`bc_setting` 에 행만 늘어납니다).

## 2026-09-22 · 집계 패널을 없애고 상태 축을 탭으로

앞선 작업(같은 날)이 조건과 집계를 한 판에 담아 위계를 정리했다면, 이번에는
**한 축에 자리 하나**라는 원칙을 끝까지 적용했습니다.

화면이 다루는 축은 셋입니다.

| 축 | 묻는 것 | 자리 |
|---|---|---|
| 범위 | 어느 모집단 | 필터 상자 |
| 사람 | 누구 것 | 필터 상자 끝 (내 신청만 · 담당) |
| 상태 | 어디까지 갔나 | **목록 위 탭** |

**1. 집계 패널을 없앴습니다**

상태 축의 자리가 패널과 탭 둘이라 늘 한쪽이 거짓말을 했습니다. 패널을 걷어내고
건수를 **탭 라벨 옆 색 알약**으로 옮겼습니다. 숫자가 그 숫자를 쓰는 컨트롤에
붙어 있으므로, 위계가 어긋날 자리 자체가 없어집니다.

```
전체 54  검토 대기 3  구매 대기 5  구매 진행 2  구비 완료 41  반려·철회 3
```

- 탭이 넷에서 **여섯**으로 늘고, 묶음(`구매 진행중 물품`)은 빠집니다.
  묶음과 낱개가 같이 있으면 또 겹칩니다
- 고른 탭은 그 단계 색으로 채워집니다. 평소에는 라벨 앞 점이 색을 맡습니다
- **`54 = 3+5+2+41+3`** 이 한 줄에서 맞아떨어져, 전체에 반려·철회가 포함되는지를
  글로 설명할 필요가 없어졌습니다
- 0건 탭은 흐려지되 **누르는 것은 막지 않습니다**. 막아 두면 왜 안 눌리는지
  설명할 자리가 없습니다
- 조회 블록의 아랫줄과 그 여백이 통째로 빠져 **약 85px** 이 목록으로 갑니다

**2. 관리자 화면의 두 축을 갈랐습니다**

탭 여섯 개에 두 축이 섞여 있었습니다. `내가 처리할 건`·`내가 맡은 건` 은 사람 축,
나머지 넷은 상태 축입니다. 상태는 탭에 남기고 사람은 필터 상자의 **담당** 으로 올렸습니다.

`내가 처리할 건` 은 이름과 달리 역할에 맞는 단계까지 정합니다. 그래서 탭을 여럿
동시에 켜는 대신, **담당이 모집단을 좁히고 건수가 그 안에서 다시 계산**되게 했습니다.
해당 없는 단계는 저절로 0건이 되어 흐려집니다.

```
담당 = 전체            전체 54 · 검토 대기 3 · 구매 대기 5 · 구매 진행 2 · 구비 완료 41 · 반려·철회 3
담당 = 내가 처리할 건   전체  7 · 검토 대기 3 · 구매 대기 2 · 구매 진행 2 · 구비 완료  0 · 반려·철회  0
```

관리자 화면에 **정렬** 항목을 새로 넣어 구성원 화면과 구조를 맞췄습니다.

**3. 기본 정렬을 처리 단계 순으로**

묶음 탭이 없어지면서 기본 화면을 정해야 했습니다. 기본 탭은 `전체` 로 두고
정렬 기본값을 `최신 요청 순` → **`처리 단계 순`** 으로 바꿨습니다. 검토 대기부터
올라오므로 **손이 필요한 건이 저절로 위로 옵니다.** 이미 있던 정렬 항목이라
새 컨트롤을 만들지 않았습니다.

관리자 화면의 담당 기본값은 `내가 처리할 건` 입니다. 지금 동작 그대로라
열면 바로 작업 큐가 보입니다.

**4. 상태 탭과 담당을 한 곳에서 풉니다**

`includes/workflow.php` 에 `bc_tab_status()` · `bc_assign_scope()` 를 뒀습니다.
화면 목록, 엑셀, 집계가 전부 이 두 함수를 보므로 서로 어긋날 수 없습니다.
예전에는 `api/requests.php` 와 `api/export.php` 가 탭 프리셋을 따로 갖고 있었습니다.

**5. 버그 — 상태를 걸렀는데 전체가 나오던 것**

`search()` 는 상태 목록에서 모르는 값을 걸러 냅니다. 그런데 걸러 낸 결과가 비면
**조건이 통째로 빠져 전체가 나왔습니다.** `0건` 을 뜻하는 센티널(`__NONE__`)이
정반대로 동작한 셈입니다. 넘어온 값이 있는데 하나도 안 남으면 `1 = 0` 을 걸어
0건이 되게 했습니다. 집계 쪽에도 같은 처리를 넣었습니다.

**확인한 것**

- `bc_tab_status()` · `bc_assign_scope()` · 둘의 교집합 계산 **16건 통과**
  (역할별 todo, 겸직, 역할 없음, 탭∩담당이 비는 경우 포함)
- PHP 6개 파일 구문 검사, `app.js` 구문 검사, CSS 중괄호 균형
- `app.js` 가 찾는 id 73개가 뷰에 모두 있는지 대조
- DB 통합 시험(`tests/workflow_test.php`)은 실 DB 연결이 필요해 돌리지 않았습니다

**바뀐 파일**

```
includes/workflow.php               (bc_tab_status · bc_assign_scope 신설)
includes/model/PurchaseRequest.php  (담당 축을 집계에 · 빈 상태 목록 처리)
api/requests.php                    (탭 프리셋을 상태/사람 축으로 분리)
api/export.php                      (화면과 같은 함수를 봄)
views/member.php                    (패널 삭제 · 상태 탭 자리)
views/admin.php                     (패널·처리구분 탭 삭제 · 정렬/담당 추가)
assets/app.js                       (renderPipe → renderStatusTabs)
assets/app.css                      (집계 규칙 삭제 · .bc-statabs 추가)
```

## 2026-09-22 · 조회 블록 통합 · 집계와 필터의 위계 정리

**1. 조건과 집계를 한 판에 (`.bc-onebox`)**

필터 상자와 집계 패널을 따로 놓으면 **아래 필터가 위 집계를 바꾸는** 모양이 되어
위아래 어느 쪽이 먼저인지 읽히지 않았습니다. 둘을 한 판에 담아 같은 층으로 만들었습니다.
판 안의 모든 것이 아래 목록을 고릅니다.

- 판 안은 가로선을 긋지 않고 **수직 여백 14px** 로만 위아래를 가릅니다
- 아래 줄에서도 **연도 전체 취합**과 **진행 상태**를 선이 아니라 **여백 14px** 로 뗐습니다
- 집계 패널이 필터 **위**에서 **아래**로 내려갑니다 (조건 → 집계 → 목록)

**2. 집계가 조회 조건 전부를 반영**

`statusCounts()` 가 연도·사용처·요청자만 받아서, 같은 상자 안인데 **요청일·검색어는
위 숫자를 안 바꾸는** 비대칭이 있었습니다. `search()` 와 같은 조건을 태워 둘이 항상
같은 모집단을 보게 했습니다. 상태와 탭만 제외합니다 — 집계가 나눠 보여 주는 축이라
여기서 걸면 자기 자신을 지웁니다.

**3. 연도 전체 취합 칸**

- 레일 안에서 빼내 **제 테두리와 옅은 바탕을 가진 판**으로 떼어 놨습니다.
  '누르는 칸이 아니다' 가 바탕색에서 바로 읽힙니다
- 너비를 넓혔습니다 (최대 250px). 반려·철회 두 항목이 여유 있게 들어갑니다
- 알약을 벗겼습니다. 칸이 이미 테두리를 가졌는데 알약까지 씌우면 상자 속 상자가 됩니다

**4. 단계 색띠를 늘 보이게**

고른 칸에만 나오던 하단 3px 색띠를 **평소에도** 깔았습니다.
네 단계를 색으로 가르는 일은 띠가, 골랐다는 표시는 칸 전체의 색면이 맡습니다.

**5. 높이 축소**

숫자 28 → 25px, 위아래 여백 14/15 → 10/12px. 칸 높이가 **약 83px → 70px** 로 줄어
목록이 그만큼 위로 올라옵니다.

**6. [내 신청만] 을 조회 항목 쪽으로**

세로 헤어라인은 **조건 | 실행** 을 가르라고 둔 선인데, 정작 조건 하나가 선 오른쪽
실행 무리에 섞여 있었습니다. 정렬 옆으로 옮겨 선 오른쪽에는 **엑셀 받기** 만 남깁니다.

**7. 버그 — 지난 연도를 골라도 "올해 전체"**

`renderPipe()` 에 `올해 전체` 가 문자열로 박혀 있어, 2025년을 고르면 2025년 숫자에
"올해" 라는 이름이 붙었습니다. 고른 연도를 그대로 씁니다.

**남은 것** (아직 정하지 않음)

- 패널에서 단계를 고르면 하위 탭 선택 표시가 그대로 남습니다. `params()` 는
  status 가 있으면 tab 을 버리므로, 화면의 선택 표시 둘 중 하나가 사실과 다릅니다
- `TOTAL` 은 반려·철회를 포함한 여섯 상태의 합인데, 화면은 전체 옆에 반려·철회를
  따로 붙여 놓아 포함 여부가 읽히지 않습니다

관리자 화면의 `내가 처리할 건` 탭에서 구매담당자의 목록이 담당 건으로 좁혀지는 것은
탭 프리셋의 일부입니다. 탭을 집계에 반영하지 않는다는 위 원칙과 같은 사안이라
따로 고칠 것은 아니고, 첫 번째 항목(탭과 패널의 축 겹침)을 정할 때 함께 결론이 납니다.

**바뀐 파일**

```
views/member.php                    (조회 블록으로 묶기 · 내 신청만 이동)
views/admin.php                     (조회 블록으로 묶기)
assets/app.css                      (.bc-onebox · 집계 전면 수정)
assets/app.js                       (요약 라벨을 연도로)
api/requests.php                    (집계에 keyword·from·to 전달)
includes/model/PurchaseRequest.php  (statusCounts 가 세 인자를 더 받음)
```

## 2026-09-21 · 집계 패널 레일 · 필터 줄 정합 · 층 사이 여백

**1. 집계 패널을 한 장의 레일로**

상자 다섯 개를 따로 놓던 것을 흰 판 한 장으로 합치고, 단계 사이에 꺾쇠를 넣었습니다.

- 칸 안의 차례를 **라벨 → 숫자** 로 통일했습니다. 오른쪽 요약 칸과 차례가 달라
  다섯 칸의 기준선이 어긋나던 것이 맞았습니다
- 단계 칸에도 단위 **건** 을 붙여 요약 칸과 어휘를 맞췄습니다
- 한 줄 안에 섞여 있던 테두리 세 가지(실선 · 3px 상단 띠 · 점선)를 레일 한 장으로 줄였습니다
